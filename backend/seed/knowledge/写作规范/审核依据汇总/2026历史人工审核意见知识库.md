## 一、数值与单位（89 + 22 + 3 + 2 条）

### R-A1　数值与单位之间必须有空格　【必报·低】

| 项 | 内容 |
|---|---|
| **触发条件** | 数字与其后紧跟的单位符号之间无空格字符 |
| **标准写法** | `7 kg`、`2 ℃`、`20 μL`、`960 GB`、`300 bp`、`5 s`、`100 V`、`2500 VA` |
| **例外条件** | ① `℃` 与中文之间不加空格（`2 ℃冰箱`）属既有写法；② 中文紧跟数字（`560 个`）风格指南未作要求；③ 公式/量纲内写法（`c (fmol/μL)`、`【Q30(%)】`）不计 |
| **修改建议** | 补空格；同一文档内若存在两种写法，以多数写法为准并全文统一 |
| **人工先例** | 「20℃」→「数字和单位之间加空格，全文通查」；「在 2℃ ~ 8℃」→「单位前面加空格」；「100μL (μL)」→「缺空格」；「24VDC，5A…」→「单位前面要加空格」；「5的前面有的有空格，有的没有，统一下」 |
| **核查范围** | 数字后紧跟 `℃ °C μL µL mL μg mg kg mg/L GB MB TB KB mm cm nm V A W kW VA kVA Hz kHz MHz bp kb s min h kg N Pa kPa MPa MHz rpm bar` |
| **证据要求** | 字符级量取（坐标连续性），确认非文本层换行伪影 |

### R-A2　单位符号本身规范　【必报·低/中】

| 项 | 内容 |
|---|---|
| **触发条件** | 单位写法错误、大小写错误、符号使用不当 |
| **标准写法** | 温度 `℃`（非 `°C`）；体积 `μL`（非 `uL`/`µL`）；频率 `Hz`（非 `HZ`） |
| **例外条件** | `°C` 混用不报（用户 2026-08-19 裁定）；`240 V~` 末尾 `~` 是交流标记，不报 |
| **人工先例** | 「单位前面要加空格」（×3 处不同文档）；「建议统一为：2 °C to 8 °C refrigerator」（英文版温度区间写法） |
| **证据要求** | 需给出同文档正确写法对照位置 |

### R-A3　数值型态：顺序、大小关系、单位换算　【必报·中】

| 项 | 内容 |
|---|---|
| **触发条件** | ① 区间两值顺序颠倒（应为从小到大）；② 大小关系写反（"应该是大于"）；③ 单位换算错误；④ 分块参数加和不等于整机值 |
| **标准做法** | **先做算术自洽校验**：把各分块参数与整机参数加和核对。若自洽 → 不得报"数值矛盾"，至多指出"未标标配/选配"（降为中/低）。若不自洽 → 报中/严重 |
| **人工先例** | 「两边的数字反过来，从小数字到大数字 中文也有这个问题」；「是否应该是大于」；「是否应是32 GB？如有修改，全文关注」；「ng 与 fmol 换算公式如下：… 前面试剂套装章节并没有提到这种测序」 |
| **证据要求** | 必须给出复算过程 |

### R-A4　表格数据与正文/图形不符　【必报·中】

| 项 | 内容 |
|---|---|
| **触发条件** | 同一参数在表格、正文、插图三处出现但数值/描述不一致 |
| **处理方式** | 表格与正文不一致 → 需先确认哪个是权威源；**表格与插图不一致**多属示意图问题，人工意见多为疑问（「感觉这个W/H/D和前面的实际图片不太一致」）→ **降为待裁定** |
| **人工先例** | 「感觉这个W/H/D和前面的实际图片不太一致 实际图片中：H似乎比W和D都多」（疑问型）；「与表格第二列"【项目流程分布】"不一致」（确定型） |

### R-B1　英文拼写错误　【必报·中（正文）/ 低（图内）】

| 项 | 内容 |
|---|---|
| **触发条件** | 存在正确词典词与原文形近词的错拼 |
| **判定方法** | 用拼写检查定位后，**必须回读上下文确认**。排除专名（PostgresSQL、zarc、fastq）、仪器型号、试剂盒名 |
| **例外条件** | ① 专名不判错拼；② 文本层提取伪影不报（须渲染页核实）；③ 用户 2026-08-19 裁定：「A task may be in one of the following status」「turn on it」等即便文本层异常也视为可接受表达；④ **平台拼写检查的命中不等于错拼**——`digestive` 即平台误报，人工明确注明「这个是在平台的拼写检查查出来的」，属**免报** |
| **修改建议** | 采用人工给出的正确拼写；**须给出被替换的原词**（如 `Barocde` → `Barcode`），不能只给整句 |
| **证据要求** | ① 错误词定位；② 同文档正确写法出现位置（证明是错拼而非变体）；③ 图内文字须 6 倍裁切渲染确认是矢量文字而非位图 |

#### ⚠ 词库方向铁律（2026-11-05 修订，旧版此处方向颠倒）

> **错误写法 = 人工在原文上划词（HTML `<mark>` 高亮）的那个词；正确写法 = 人工意见中给出的替换词。**

## 三、术语与用词统一（40 + 2 + 5 条）

### R-C1　同一概念在文档内多种写法　【必报·中】

| 项 | 内容 |
|---|---|
| **触发条件** | 同一对象在文档内出现两种及以上写法 |
| **定级四问** | ① 两种写法是否指向**同一对象**？② 是否属**不同标准体系/产品型号/配置项**（是则不报）？③ 是否有兜底声明？④ 用户是否真的无法理解？ |
| **例外条件** | ① 不同标准体系的标准名本来就不同（GB/T 18268「电设备」vs GB/T 42125「电气设备」）；② 分属不同产品型号/配置项的差异属正常；③ 同一文档内重复同一错误写法**不构成"不统一"**；④ 两套编号体系一律不上报 |
| **标准做法** | 采用多数写法；并**全文扫描**同类问题（人工明确要求"通查"） |
| **人工先例（错误→正确）** | `涡漩振荡器`→`涡旋振荡器`（全文其余 17 处均正确）；`表示如/表示该`→`表明`；`展示`→`显示`；`包含序`→`包括`；`即刻置`→`立即`；`的清洗液或`→`清洁剂`；`操作平台`→`操作台`；`洗`/`消毒`→`周清洁、月清洁`（中文先行，英文再做对应调整）；`for later`→`until use`；`position, location`→统一其一；`wash type`/`washing type`→统一其一；`cover slip`/`coverslop`→统一其一；`chip`→`flow cell`；`自检`（两处是否同一概念）→确认后统一 |
| **证据要求** | 必须给出全文该词各写法的出现次数 |

### R-C2　同义概念命名不统一（隐性不一致）　【必报·中】

| 项 | 内容 |
|---|---|
| **触发条件** | 前文已用某名称描述某对象，后文换用另一名称描述同一对象 |
| **人工先例** | 「前文有"试剂预载"这个描述，应该是相同概念，建议统一用词」；「两个"自检"是同一个概念吗？是否可以统一用词」；「是否是相同概念」 |
| **处理方式** | 需回读前文确认确为同一对象后才能报；不确定 → 待裁定 |

### R-C3　专名/型号大小写统一　【必报·中】

| 项 | 内容 |
|---|---|
| **触发条件** | 同一专名在文档内大小写不一致 |
| **人工先例** | 「产品型号应为 PrepALL（全文其余 20 处均作 PrepALL）」；「试剂套装表及全文其余 6 处均写作组合型号 G99 FCL SE100/PE50」；「需要统一大写首字母吗」 |
| **证据要求** | 必须给出"全文其余 N 处"的计数，这是定级的核心证据 |

### R-D1　中文语境使用半角标点　【必报·低】

| 项 | 内容 |
|---|---|

## 十三、如何在审核中应用本知识库

### 13.1 判定流程

```
扫描命中 → ① 是否命中免报清单？（§ 十一）→ 是 → 排除
        → ② 是否为疑问型措辞？（R-I1）→ 是 → 待人工裁定
        → ③ 是否为"同一对象"？（R-C1 四问）→ 否 → 排除
        → ④ 是否有兜底声明？→ 是 → 降级
        → ⑤ 数值类是否算术自洽？（R-A3）→ 自洽 → 不得报"数值矛盾"
        → ⑥ 是否需全文扫描/跨版本同步？（R-E2）→ 是 → 标注同步范围
        → ⑦ 定级：严重/中/低
```

### 13.2 证据要求（写进报告"证据"栏）

| 问题类型 | 必备证据 |
|---|---|
| 拼写/错别字 | 错误词 + 同文档正确写法位置（字符级确认） |
| 术语不统一 | 全文各写法出现次数 + 位置清单 |
| 数值/单位空格 | 字符级坐标量取（非文本层伪影） |
| 括号不配对 | `rawdict` 全角/半角计数闭合 + 逐处归因 |
| 中英对照 | 中英双方位置双向举证 |
| 交叉引用 | 实测偏移量 + 目标页原文回读 |
| 货号/型号 | 全文 token 去重统计 + 正确写法 |
| 图表编号 | 编号连续性 + 引用目标实测 + 语义比对 |

### 13.3 报告写作约束（与既有偏好一致）

1. **一个问题只出现一次**：正式问题合并为单张表（级别｜位置｜问题→建议），通过项压成一段单行列举。
2. **位置三段式**：章节号 + 章节标题 + 具体小标题/表名/行名；多位置用 `<br>`。
3. **修改建议不得等于缺陷原文**：低可见度修改（删字/换标点）须明确标出被删/被换的具体字符、码位、上下文及同文档对照位置。
4. **统计三处一致**：表 vs 结论句 vs 落款；且结论句与问题表双向对账。
5. **元信息必含**「审核工具：WorkBuddy（AI 文档审核）」+ 末尾落款。
6. **待裁定表另设「位置」列**，与正式问题表分开。
7. **引用人工先例必须可回溯**：写出「文档号 + 页码」，指不到就只能写「本次新发现」。

## 十四、词库与统计的溯源方法（2026-11-05 新增，可复用于任何人工意见语料）

> 本节是本轮修订过程中踩过的坑的沉淀，**任何从人工批注里提炼规则/词库的任务都应照此执行**。

### 14.1 为什么必须溯源

从 3323 条人工意见里自动抽词库，极易产出**方向颠倒**的错误：人工意见「拼写错误，single」中，`single` 是**正确写法**，
若按"意见里出现的词 = 错误词"抽取，就会把正确词记成错误词——**照此改稿会把文档改错**。

### 14.2 错误写法的唯一可靠来源：HTML 划词高亮

汇总 HTML 中，每张批注卡的 `<div class="orig">` 段用 `<mark>【…】</mark>` 标注**人工划词的位置**。
- **错误写法** = 划词片段中的错词；
- **正确写法** = 人工意见中明确给出的替换词（形如「拼写错误，X」「应该是：X」「统一为：X」）。

> **重要例外**：人工大量以**批注截图**方式标注（无划词文本），此时错误写法只出现在意见文本里。
> 因此判定不能只看划词，须做**三级证据分级**：
> **A 级** = 划词命中；**B 级** = 意见中点名该词并紧邻判定词（应为/错别字/统一为…）；**C 级** = 提及但非紧邻，需人工复核；**D 级** = 全语料无出处。

### 14.3 落地脚本（已固化）
