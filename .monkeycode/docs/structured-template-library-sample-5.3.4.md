# 结构化模板库样例：5.3.4 安装样本制备卡

本文把 `DNBelab-D4RS_试剂套装_句子分类汇总.md` 中的 `5.3.4 安装样本制备卡` 抽成一份结构化模板库样例，目标是说明模板应该怎么写、哪些字段最关键、哪些句子适合自动替换。

## 1. 推荐字段

建议每条模板至少包含以下字段：

| 字段 | 说明 | 写法要求 |
| --- | --- | --- |
| `template_id` | 模板编号 | 保持唯一，便于日志定位 |
| `section` | 所属章节 | 建议保留到小节级别，如 `5.3.4 安装样本制备卡` |
| `scene` | 操作场景 | 写成稳定场景名，如 `制备卡安装` |
| `source_step` | 来源步骤号 | 例如 `5.3.4-4` |
| `template_text` | 标准输出句 | 写成最终想输出的标准句式 |
| `intent_type` | 句子类型 | 例如 `ui_navigation`、`device_state`、`action`、`check`、`warning` |
| `actions` | 动作词 | 多个动作用 `;` 分隔 |
| `objects` | 核心对象 | 操作对象、目标界面、目标部件都写进来，用 `;` 分隔 |
| `conditions` | 前置条件 | 没有可留空 |
| `result` | 结果或状态 | 例如 `进入装载制备卡界面`、`开始建库` |
| `synonyms` | 同义表达 | 只写常见等价说法，格式建议 `原说法=标准说法` |
| `auto_apply` | 是否自动替换 | `yes` 或 `no` |
| `guard_notes` | 守卫说明 | 说明什么情况下允许替换 |

## 3. 这份样例怎么用

### 3.1 自动替换优先用这些字段

程序优先依赖以下信息做召回和守卫：

- `template_text`
- `actions`
- `objects`
- `conditions`
- `result`
- `synonyms`
- `auto_apply`
- `guard_notes`

这几列已经够系统判断三件事：

1. 原句想做什么
2. 原句在操作什么对象
3. 这条模板能不能安全替换

### 3.2 哪类句子更适合拆成多条模板

以下句子适合拆分：

- 同时包含两个动作的句子
- 同时包含条件和动作的句子
- 同时包含界面跳转和设备状态变化的句子

例如 `5.3.4-9` 就天然是复合句，但这里仍保留成一条模板，因为这句操作顺序固定，而且四个要素 `确认 -> 点击确定 -> 进入界面 -> 载台收回` 连得很紧。

如果后续出现更多变体，也可以把它拆成两条：

- `确认制备卡已放至载台后，点击【确定】。`
- `进入装载制备卡界面，载台自动收回。`

### 3.3 哪类句子更适合只做建议，不做自动替换

以下句子建议 `auto_apply = no`：

- 参考文档句
- 长说明句
- 强依赖图号、货号、版本号完整性的句子
- 容易因为轻微改写而损失信息的句子

当前样例里的 `T-5.3.4-07` 就属于这类。

## 4. 后续扩展建议

如果你准备把整份句式文件都改成结构化模板库，我建议按下面顺序推进：

1. 先整理 `5.3.4`、`5.4` 这类高频操作句章节。
2. 每条模板只保留一个稳定输出句，避免一条模板里塞多个可选版本。
3. 同义词列只维护高频等价说法，避免把近义但语义不同的词混在一起。
4. 对 `ui_navigation`、`action`、`check` 三类句先做自动替换。
5. 对 `warning`、`reference`、`description` 三类句先做候选展示。
