## 一、可读性评分模型

### 1.1 总体框架

综合评分 = Σ(维度得分 × 权重)，满分 100。每个维度独立计算 0–100 分并给出样本例句（可点查证据），总分不做任何隐藏修正。

| 维度 | 权重 | 依据 |
|---|---|---|
| 平均句长 sentence_length | 25% | 技术写作规范中句长对可读性影响最直接（ASD-STE100 等规范均以句长为核心管控项） |
| 术语密度 term_density | 20% | 术语堆叠是 B 端手册主要阅读障碍，但合理密度是必要的，权重低于句长 |
| 被动句比例 passive_ratio | 20% | 操作类文档要求明确执行主体，被动句掩盖责任方 |
| 段落长度 paragraph_length | 15% | 影响较低：长段常由长句导致，与句长维度部分重叠，降权避免重复惩罚 |
| 修饰词堆叠 modifier_stack | 20% | 连续定语/形容词堆叠是中文与英文技术文档通病 |

### 1.2 各维度公式与阈值（v1.1 区间制）

v1.1 由 v1.0 的「单向阈值制」（指标 ≤ 满分线即 100 分）改为**区间制**：指标落入理想区间 `[ideal_lo, ideal_hi]` 得满分；低于下限按短侧梯度 `k_short` 扣分，高于上限按长侧梯度 `k_long` 扣分，两侧梯度独立。分数经 `_clamp_score` 限制在 0–100。

```
_band_score(avg, ideal_lo, ideal_hi, k_short, k_long):
  avg < ideal_lo 且 k_short > 0  → 100 − (ideal_lo − avg) × k_short
  avg > ideal_hi 且 k_long  > 0  → 100 − (avg − ideal_hi) × k_long
  否则                           → 100
```

| 维度 | 语言 | 理想区间 | 短侧扣分（k_short） | 长侧扣分（k_long） |
|---|---|---|---|---|
| 平均句长 | 中文 | 15–40 字 | 每短 1 字扣 1.0 分 | 每超 1 字扣 1.5 分 |
| 平均句长 | 英文 | 8–20 词 | 每短 1 词扣 2.0 分 | 每超 1 词扣 3.0 分 |
| 术语密度 | 中/英 | 5%–15% | 每低 5 个百分点扣 10 分（k=200） | 每高 5 个百分点扣 8 分（k=160） |
| 被动句比例 | 中/英 | 0–10% | 不扣分（k_short=0：被动少不是问题） | 每高 5 个百分点扣 10 分（k=200） |
| 段落长度 | 中文 | 30–150 字 | 每短 2 字扣 1.0 分 | 每超 5 字扣 1.0 分 |
| 段落长度 | 英文 | 10–80 词 | 每短 0.4 词扣 1.0 分 | 每超 2 词扣 1.0 分 |
| 修饰词堆叠 | 中/英 | 0 处 | — | 每处扣 4 分（`100 − count × 4`；中文 ≥3 连「X 的」，英文 ≥3 连形容词） |

设计动机（外部评审 P0 采纳项）：
- **短侧也扣分**：v1.0 只罚「过长」，导致电报体短句、零术语密度的浅内容与优质文档同样拿满分，无区分度；
- **被动句只扣高不扣 0%**（用户裁定）：被动句占比 0 不代表文档有问题，`k_short=0` 语义为「低侧不触发扣分」；
- 中英文区间差异依据：中文一字约对应英文 0.5–0.6 词的信息量，15–40 字 ≈ 8–20 词。

### 1.3 综合评级与评级抑制

| 综合分 | 评级 |
|---|---|
| ≥ 85 | excellent |
| ≥ 70 | good |
| ≥ 55 | fair |
| < 55 | poor |

**评级抑制（防误导）**：任一维度 < 55 分时综合评级封顶 fair；任一维度 < 40 分时封顶 poor。触发时报告输出 `level_note` 说明下调原因。

### 1.4 样本量三档（v1.1 新增，外部评审 P0 采纳项）

按提取句数分档，防止「样本不足仍给高分」：

| 样本档位 | 句数 | 行为 |
|---|---|---|
| insufficient | < 100 | **不评分**：维度 score 置 None、综合评分 None、评级 insufficient；报告渲染为「样本不足（未评分）/ 维度 N/A」，并提示改用 PDF 原件或本地 HTML 上传 |
| limited | 100–500 | 正常评分，但综合评分旁显式标注「（样本有限）」，warnings 提示评分仅供参考 |
| sufficient | > 500 | 正常评分，无额外标注 |

客观结构统计（第三节）不受样本档位影响，样本不足时仍输出。

## 二、术语库（term_density 的判定基础）

三层来源，命中任一即计为术语：

1. **内置领域术语**（`_BUILTIN_EN_TERMS`）：测序（sequencing/flowcell/adapter/barcode…）与图像分析（segmentation/ROI/thresholding…）两大领域，约 150 词条；
2. **平台词典**（`app/dictionary/technical_terms.txt`）：与平台其他模块共享；table/figure/step 等普通词已列入排除集；
3. **强术语特征**（无需词条）：含数字的型号（NextSeq 2000、Q30）、含连字符的复合词（RNA-seq）、≥2 字符全大写缩写（DNA、PCR、MGI）。

匹配规则：精确匹配 + 轻量词干（复数 -s/-es/-ies），大小写不敏感。

**术语样本（v1.1 新增，外部评审 P1 采纳项）**：术语维度的问题例句由「零散术语词列表」改为「密术语句子」——收集 ≥3 个术语命中且术语占比 ≥25% 的句子取 top5，作为「术语密度过高」的直接证据，避免把孤立术语词当问题刷屏。

> 历史缺陷（已修复）：旧版以「长度 > 6 的英文单词」判术语，把 technical/information 等普通词全部误报，实测密度虚高至 48.5%。

## 三、结构统计（客观指标，不做主观评分）

| 指标 | PDF 口径 | HTML 口径 | DOCX/MD |
|---|---|---|---|
| 页数 | `doc.page_count` | 恒为 1 | 按 pages_text 兜底 |
| 章节数 | 标题行正则（保守启发式） | `<h1>–<h3>` 标签计数（优先） | 标题行正则 |
| 图片数 | 嵌入图按 xref 去重（复用 logo 不重复计） | 正文区 `<img>` 计数（剔除 nav/header/footer） | 暂不支持（notes 说明） |
| 表格数 | `page.find_tables()` 线框检测（>300 页跳过控耗时；需单元格内有文字） | 正文区 `<table>` 计数 | 暂不支持（notes 说明） |
| 安全警告数 | 行首 WARNING/CAUTION/DANGER/NOTICE/警告/注意/危险/警示（文本关键词标记） | 同左 | 同左 |
| 警告符号（文本层） | ⚠/☠/🛡/🚧/🚫/⛔ 等 unicode 符号计数 | 同左（HTML 分支解析器统计） | 同左 |

**安全警告 0 标注（v1.1 新增，外部评审 P1 采纳项）**：`warning_count == 0` 时自动追加说明「检测依赖文本关键词匹配，图标或特殊排版呈现的安全提示可能未被统计，建议人工复核」，避免把「0 警告」当作竞品合规结论；检测到警告符号时同步提示「疑似图标型安全提示」。

标题行启发式的保守设计：编号标题要求至少两级（如 3.2）以避开「1. 操作步骤」，行长度 ≤ 60 且不以句读结尾，Chapter/Appendix/第X章 直接匹配。计数为近似值，报告中已注明口径。

## 四、编辑工具识别置信度规则

### 4.1 PDF 输入

| 证据来源 | 置信度 | 规则 |
|---|---|---|
| producer/creator 元数据命中 | high | 唯一例外：仅命中 Adobe Acrobat 且无其他工具时降 medium（多半只是「另存为」） |
| 嵌入字体推断宿主工具 | medium | 仅作佐证，不单独定论 |
| 文本指纹（LaTeX 标记/软连字符等） | low | 仅在元数据与字体均未命中时展示 |

**浏览器打印导出识别与内嵌链接反查（v1.1 新增，外部评审 P1 采纳项）**：
- producer 命中 Skia/Chrome/Edge 等打印链路，或 creator 含 Chrome/Edge → 识别为「浏览器打印」类（二手资料），并在报告「导出/来源说明」注明：工具识别仅代表打印链路，无法直接确认原创编辑工具；分页断行为浏览器渲染结果，句长/段落统计可能受影响；
- 对 PDF 用 `page.get_links()` 反查内嵌链接（限 50 页 / 40 条）：命中 `/content/`、`/skins/`、`.htm`、`/topics/` 特征 → 提示「疑似 HAT（如 MadCap Flare）导出」，弥补打印链路无法直接识别原创工具的缺口。

识别库（`_TOOL_PATTERNS`，25 条模式、19 种工具）：InDesign、FrameMaker、QuarkXPress、Pandoc、DITA-OT（producer "DITA Open Toolkit"/"dita-ot"/"ditaot"）、oXygen XML Editor、LaTeX 三变体（pdfTeX/XeTeX/LuaTeX，泛化条目自动去重）、Word、LibreOffice、OpenOffice、WPS、Distiller、Acrobat、Prince XML、PDFium、Chrome/Edge 打印、macOS Quartz、Pages。

### 4.2 HTML 输入（证据链模型）

每个工具按独立证据计数：**≥2 条 → high，1 条 → medium，0 条 → 未知**。

| 工具 | 证据类型 |
|---|---|
| MadCap Flare | URL 含 /Content/ 或 /Skins/、脚本依赖 MadCap*、CSS 位于 Skins/Content 目录、data-mc-* 属性、MadCapAll.js 引用、根元素 `xmlns:MadCap` 命名空间、`data-mc-help-system-file-name` 属性（后两条为 v1.2.2 新增，实测 Illumina 全站具备，解决此前 Flare 站仅命中 1 条证据、置信度上不去的问题） |
| Adobe RoboHelp | whutils/whmsg/whver/whstub.js 脚本、rgforms/RoboHelp 标记 |
| DITA-OT | URL 含 /topics/、/concepts/、/tasks/，class 含 topic/concept/task（排除 task-list 等扩展类名），data-dita-* 属性，meta generator |
| 文档站点框架 | meta generator（Docusaurus/VitePress/VuePress/GitBook/Sphinx/MkDocs/ReadMe），medium |

同一工具被结构特征与 meta generator 同时命中时证据合并、可升 high，不产生重复条目。

## 五、HTML 正文抽取与全站递归爬取

### 5.1 正文抽取与入口页识别

- 剔除 nav/header/footer/aside/script/style/form/template 等骨架标签内全部文本；
- 优先取 `<main>`/`<article>` 正文，正文 ≥ 400 字符才采用，否则回退全页（已去噪）并输出「JS 渲染受限」警告；
- 抓取安全：仅公网 http/https（DNS 解析校验，拒环回/私网/保留地址）、仅 80/443、5 MB 上限、20 s 超时；
- **入口页识别（v1.1）**：URL 路径含 `/frontpages/`、`/index`、`/home`、`/default`、`/toc` 等特征，或全文 < 500 字符 → 报告提示「当前为封面/导航页，建议选择子页面或上传完整 HTML 包」——**仅提示、不阻断**：入口页仍作为爬取起点，从它的子链接继续抓取正文 topic 页。

### 5.2 全站递归爬取（v1.2.2 新增，用户裁定变更）

**裁定变更（2026-08-24）**：用户明确「所有子页面、子 topic 都需要爬取，不只是入口页面」，推翻此前「只识别入口页 + 不递归爬取（裁定③）」。仅分析入口页会导致站点体验被系统性低估——面包屑/搜索/TOC 等结构维度只测到壳页面。爬取策略由此前「入口页 + 尝试脚本仅一层」升级为平台正式能力（`competitor_crawl.py`，API 层 `_parse_web_document` 默认执行）。

| 项 | 规则 |
|---|---|
| 算法 | BFS 广度优先，从入口 URL 出发抓取同域全部文档子页面/topic |
| 同域约束 | 仅与入口 hostname 完全一致的链接入队（子域视为跨域，防范围失控） |
| 去重 | URL 规范化键 `_norm_key`：去 fragment/尾斜杠、host 小写、query 参数排序 |
| 链接过滤 | 二进制/资源扩展名（pdf/zip/png/css/js/office/字体/视频等 39 类）与 `javascript:`/`mailto:`/`tel:`/`data:`/`ftp:` 等非文档链接不入队 |
| 边界防失控 | `max_pages=50`（含入口）、`max_depth=4`（入口 depth=1，`depth ≥ max_depth` 不再扩展子链接）、页间礼貌延迟 0.2 s |
| 安全 | 入口预校验 `assert_public_http_url`；每个子链接均复用 `fetch_html`（协议/端口白名单 + DNS 公网校验 + 超时/体积上限），**无旁路请求通道**（链接抽查与爬取共用同一安全抓取链路） |
| 失败容错 | 单页抓取失败计 `failed` 并跳过，不中断整站爬取 |
| 汇总 | 各页正文合并 `combined_text` 供可读性/结构/内容类体验维度；结构统计（img/table/heading/警告符号/警告行）全站累加；每页原始 HTML 经 `pages_html` 仅内存透传体验三维度做多页聚合，**不落库** |
| 空站语义 | 全站无可提取正文 → HTTP 422（与单页「JS 骨架页」口径一致，提示改用本地 HTML 上传）；有部分正文但整体低内容 → 保留低内容警告走 200 |

## 六、体验三维度（v1.2 新增：可获得性 / 易查找性 / 可用性）

### 6.1 理论依据与总体框架

依据《Developing Quality Technical Information》（Hackos & Stevens, 2nd ed.）的质量特征体系——「文档好不好，看是否易于 X」：
- **Easy to find**（易查找：组织 Organization + 可检索 Retrievability）→ 易查找性 Findability 与可获得性 Access；
- **Easy to use**（易用：任务导向 Task Orientation，DQTI 强调文档应围绕用户任务组织）→ 可用性 Usability。

三个维度与需求说明书 V1.2 §3.3–3.5 对齐，输出结构统一：

```
{ "overall_score": 综合评分, "level": 评级, "dimensions": { 维度键: {score, grade, note, applicable} }, "notes": [N/A 说明] }
```

- **每维度**输出定性分级 `grade`（如「无门槛/需登录/多格式/响应式/完整/部分/高/中/低/有/无」）+ 0–100 评分 `score` + 检测说明 `note` + 适用性 `applicable`；
- **综合评分 = 适用维度加权平均**（`Σ(score×weight) / Σ(weight)`，仅统计 applicable=True 且 score 非 None 的维度）——N/A 维度权重不计入分母，避免 PDF 输入因缺少网页维度被系统性扣分；
- **综合评级**沿用四级：≥85 excellent / ≥70 good / ≥55 fair / <55 poor；
- **输入差异**：HTML 输入全维度自动检测；PDF 输入无网页属性（站内搜索/移动端/多语言/URL/SEO 等）的维度输出 `applicable=False + score=None + grade=None`，`notes` 注明「不适用于当前输入，已置 N/A（人工辅助维度可在导出后手动补充）」；
- **多页聚合（v1.2.2 新增，全站递归爬取场景；v1.2.3 修正口径）**：`pages_html ≥ 2 页` 时，**结构类维度**（站点级属性：登录门槛/站内搜索/移动端/多语言/离线下载/面包屑/TOC/索引术语表/SEO/关键内容直达）由「单页检出」改为「**页均得分聚合**」——对每页 HTML 执行检测取该页得分（0–100），聚合分 = 各页得分算术平均（v1.2.3 起；v1.2.2 曾按「检出页数比例」计分，对多级评分函数如登录门槛 40/70/100、TOC 20/60/100、SEO 20/60/100 会把「部分达标」误放大为满分，已修正），等级按页均得分映射：≥80 普遍检出 / ≥50 部分检出 / >0 少数检出 / 0 无，note 标注「N/M 页检出」（N=score>0 的页数）。**二值检测（搜索/面包屑/索引/直达 100 或 0）下页均得分 ≡ 检出比例×100，与 v1.2.2 行为一致**；**内容类维度**（版本透明度/任务导向标题/步骤完整性/错误恢复/一致性/可操作指令）基于合并全文不变；**URL 语义化**仅按入口 URL 单值判定（站点级单一属性）；**格式选择**仍按入口页下载链接枚举（跨页下载链接已并入各页正文）。

### 6.2 可获得性 Access（§3.3，7 维）——用户能否「拿到」文档

| 维度 | 权重 | 检测规则 | 分级 |
|---|---|---|---|
| 获取门槛 access_barrier | 20% | HTML 表单检测：`input[type=password]` → 需登录；`input[type=email]` → 需邮箱 | 无门槛 100 / 需邮箱 70 / 需登录 40 |
| 格式选择 formats | 15% | 页面下载链接按后缀枚举（pdf/docx/doc/epub/zip/xlsx/pptx） | ≥3 种 100 / 2 种 80 / 1 种 50 / 仅在线 30 |
| 站内搜索 has_search | 15% | `input[type=search]` 或 name 含 q/search/query/keyword，或 form[role=search]/action 含 search；**v1.2.2 补强：`<html data-mc-search-type>` 根属性（MadCap Flare 等 HAT 的搜索能力声明，UI 由 JS 注入、静态 DOM 无输入框）→ 有（HAT 内置）** | 有 100 / 无 0 |

权重动机：**获取门槛最重（20%）**——拿不到文档其余分析免谈；格式选择与站内搜索直接决定「拿到」成本；离线可用性保证无网环境可读。

**多页聚合（v1.2.2）**：获取门槛 / 站内搜索 / 移动端 / 多语言 / 离线可用性 5 个站点级维度按**页均得分**聚合（v1.2.3 起，见 §6.1）；格式选择按入口页下载链接枚举；版本透明度基于合并全文文本检索。

### 6.3 易查找性 Findability（§3.4，7 维）——用户能否快速「找到」内容（DQTI Easy to find）

| 维度 | 权重 | 检测规则 | 分级 |
|---|---|---|---|
| 站内搜索 has_search | 15% | 同 §6.2 | 有 100 / 无 0 |
| 目录完整性 toc_completeness | 20% | HTML：导航元素（class 含 toc/menu/tree/sidenav/sidebar）或大纲层级（h1–h6 最大最小差+1）；PDF：书签 `get_toc()` 层级 ≥2，无书签退目录页文本 | 完整 100 / 部分 60 / 无 20 |

**多页聚合（v1.2.2）**：站内搜索 / 目录 / 面包屑 / 索引术语表 / SEO 元数据 / 关键内容直达 6 个站点级维度按**页均得分**聚合（v1.2.3 起，见 §6.1）；URL 语义化仅按入口 URL 单值判定。

### 6.4 可用性 Usability（§3.5，6 维）——用户能否「用」文档完成任务（DQTI Easy to use 任务导向）

| 维度 | 权重 | 检测规则 | 分级 |
|---|---|---|---|
| 任务导向标题 task_oriented_headings | 20% | 标题行（复用 §三 标题启发式）去编号后以**动名词/祈使动词**开头（Installing/Configuring/Setting up/How to/安装/配置/设置/使用…，中英各约 40 词表）；**名词形式（Installation/Configuration）不视为任务导向**——标题应描述「动作」而非「概念」 | ≥60% 高 100 / ≥30% 中 65 / 低 30 |
| 步骤完整性 step_completeness | 20% | 编号步骤行（`^\d{1,2}[.)、]`）+ 前置条件（Before you begin/prerequisite/requirements/前置条件/开始前）+ 预期结果（Expected result/What to expect/预期结果/完成后） | 步骤+前置+结果 100 / 步骤+其一 65 / 仅步骤 50 / 无步骤 25 |
| 错误恢复信息 error_recovery | 15% | troubleshooting/FAQ/error codes/常见问题/故障排除/错误码 等章节关键词 | 有 100 / 无 0 |

| 可操作指令 imperative_instructions | 15% | 编号步骤行中以祈使动词开头（Install/Click/Press/Ensure/安装/点击/按/确保…）的占比 | ≥60% 高 100 / ≥30% 中 65 / 低 30 |

### 6.6 检测局限（诚实披露）

1. 搜索入口：v1.2.2 起识别 `<html data-mc-search-type>` 根属性（Flare 等 HAT 的搜索能力声明），**Flare 站搜索漏检已解决**；但未声明根属性、纯 JS 渲染搜索框的框架站仍可能低估；
2. Flare 左侧 TOC 由 JS/iframe 渲染时静态 HTML 无 nav.toc 元素 → toc_completeness 按大纲层级判定；多页聚合（页均得分）后仍只反映「已抓页面子集」，可能低估；
3. 任务导向标题复用「编号标题」启发式，无编号的 `<h1>`（如 Flare topic 标题 "System Overview"）不计入 → 标题占比可能低估；
4. 步骤编号依赖文本层格式（`1)` `2.` 等），HTML 抽取丢号时 step_count 漏计；
5. 版本透明度依赖 footer/页眉文本，若正文抽取剔除 footer 则可能漏检版本号——全站合并全文后多页 footer 独立成段，命中概率较单页提升；
6. 链接抽查仅覆盖站内链接且限 5 条，外链/深链不保证覆盖；网络受限时自动降级不评分（`applicable=False` 并注明）；
7. **爬取上限（v1.2.2 新增）**：`max_pages=50` / `max_depth=4` 下，深层目录（>4 层）或大型站点（>50 页）只能覆盖子集，聚合比例基于「已抓子集」而非全站；同域限制意味着子域托管的文档站（如 `docs.example.com` 与 `example.com` 分属不同子域）不会跨域抓取。

## 七、洞察引擎（v1.1 四分类重构）

规则层（确定性）输出四类洞察，去重（area + action 前 20 字）后 P1 在前、最多 10 条：

| 类别 | 触发 | 优先级 |
|---|---|---|
| 竞品弱项机会 | 维度得分 < 55 | P1 |
| 竞品基准（高分合并） | 维度得分 ≥ 85，合并为单条，evidence 附前三强维度 | P2 |
| 中分改进空间 | 维度得分 55–70 | P2 |
| 竞品基准/工具链/图文密度/安全警告/对比基线/总体 | 工具链双形态（在线+打印 PDF）、图文比、warning=0 风险、我方优劣占位（无基线时引导录入）、总体评级 | P1/P2 |

**v1.1 变化（外部评审 P1 采纳项）**：v1.0「逐维度刷对标检查」导致洞察同质化刷屏，v1.1 将高分维度合并为单条「竞品基准」，新增结构图文密度、安全警告风险、对比基线占位三类；「我方优势/劣势」需我方手册基线数据，无基线时以占位条引导（用户裁定：四类全做，占位待数据）。

AI 层可选（`COMPETITOR_AI_INSIGHT` 开关），仅接收结构化指标（不传全文，token 成本恒定约 1k），失败自动降级为纯规则。

**体验维度洞察（v1.2.4 新增）**：规则层新增第三组来源——将体验三维度（Access/Findability/Usability 共 19 维）纳入洞察生成，与可读性维度并列：

- **映射表 `_EXPERIENCE_DIM_ACTIONS`**：为每个体验维度维护 `label`（中文维度名）与 `action`（可执行改进建议）。建议面向「我方文档团队」给出可落地的对比行动（如站内搜索缺失 →「配置站内检索功能；若暂时无法实现，应提供结构化目录、索引术语表与面包屑导航作为补偿」），而非仅陈述竞品现状；
- **触发规则 `_experience_insights`**：遍历三组维度，`applicable=False`（不适用）或 `score=None`（未评分）的维度直接跳过；`score < 55` 生成 P1「竞品弱项机会」（我方应补齐形成差异化优势），`55–70` 生成 P2「改进空间」（我方保持即可领先）；`area` 格式如「可获得性 · 站内搜索」，`evidence` 附维度 note 与分数；
- **签名贯通**：`generate_rule_insights` / `generate_ai_insights` / `generate_insights` 新增 `experience` 参数（默认 None 向后兼容），由 API 层 `_run_analysis` 将 `analyze_experience` 结果透传，解决「洞察生成器只有可读性、无体验信息」的盲区；规则层在 `_dimension_insights` 之后追加体验洞察，去重后仍按 P1 在前、最多 10 条；`generate_insights` 最终上限 12 条；
- **AI 层联动**：`generate_ai_insights` 将体验三组综合分与 P1/P2 弱项维度摘要纳入 prompt（不传全文），供 AI 生成综合建议；
- **前端互补**：`Competitor.vue` 内置与后端映射表平行的 `dimActions` 表，通过 computed 属性从 `experience` JSON 实时渲染「体验维度改进建议」区块（结构化结果卡与详情对话框各一份），与后端 insights 互补、不重复请求接口。

多文档对比（另见代码文档）：2–5 任务维度分数矩阵 + 并列最高分标记 + 综合排名 + 雷达图；有我方基线时逐维度 Δ≥8 报差距，无基线时极差 ≥15 报分化点。**「与我方文件对比」入口（v1.2.4 新增）**：分析结果面板新增对比按钮，跳转 `/competitor/compare?preselect={taskId}`，对比页 `onMounted` 读取 query 自动勾选对应任务，支持历史分析一键进入对比。

## 八、报告渲染口径（v1.2 同步）

## 九、已知局限与校准方法

### 9.1 已知局限（诚实披露）

1. 章节数为启发式近似值（无 PDF 大纲时按标题行正则）；
2. PDF 表格检测依赖线框与单元格文字，无边框/样式化表格可能漏计；
3. 被动句判定为规则式（中文「被/受到/由…完成」，英文 be+过去分词），存在漏判/误判；
4. 术语库以测序/图像领域为主，其他领域（超声等）密度指标偏低需扩充词条；
5. 权重与阈值 v1.1 为工程经验值（区间制参数已按保守方向设定），**尚未用大规模真实手册集校准**；
6. 警告符号统计依赖文本层 unicode 符号，嵌入图片中的警告图标无法统计（已提示人工复核）；
7. 体验三维度检测局限见 §6.6（HAT 搜索识别已补、纯 JS 搜索框/TOC 渲染漏检、无编号标题不计入任务导向、步骤编号提取依赖文本层格式、爬取上限 50 页/4 层仅覆盖子集等）。

### 9.2 校准方法（CLI）

```bash
cd backend
python scripts/calibrate_competitor.py <手册文件或目录>... --out calibration.md
```

输出逐文档原始指标 + 评分 + 中位数分布。复核准则：

- 公认优质的手册某维度普遍 < 70 分 → 该维度区间过窄或梯度过严，放宽；
- 公认晦涩的文档普遍 > 85 分 → 梯度不足，加严；
- 调整后修改 `_dim_*` 函数中的区间/梯度参数，重跑校准直至分布合理，再同步更新本文档版本号。

> 报告页脚「评分方法：规则引擎 v1.2」即指向本文档；算法调整后必须递增版本并在本文档记录变更。
