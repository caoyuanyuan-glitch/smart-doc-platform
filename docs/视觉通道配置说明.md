# 视觉 / 版面通道配置说明

**核查日期**：2026-11-19
**结论**：视觉/版面通道代码完整，模型名全部通过环境变量配置，无硬编码。当前无视觉 key 状态下通道会优雅降级（不崩溃），你后续只需补 key + 设模型名即可启用，无需改代码。
**验证方式**：`QWEN_VL_MODEL=qwen3.8-flash`、`KIMI_VL_MODEL=kimi-k2.6` 已被代码正确读取；无 key 时视觉函数返回 `error/qwen_unavailable` 而非抛异常；版面几何信号通道不依赖视觉模型，始终可用。

## 一、你要补的配置（填到 `backend/runtime.env`）

```env
# 视觉复核总开关（默认已开，1=开）
REVIEW_PDF_VISUAL_VERIFY=1

# 视觉模型名 —— 按你说的填
QWEN_VL_MODEL=qwen3.8-flash
KIMI_VL_MODEL=kimi-k2.6

# 这两个模型的 API key（你后续补）
QWEN_API_KEY=<你的 qwen key>
KIMI_API_KEY=<你的 kimi key>
# Kimi 也接受别名 MOONSHOT_API_KEY

# provider 顺序：先 qwen3.8-flash 再 kimi-k2.6
REVIEW_VISUAL_PROVIDERS=qwen,kimi
```

> 注：`REVIEW_VISUAL_PROVIDERS` 默认是 `kimi,qwen,visual`。若要按你指定顺序（qwen 先），显式设为 `qwen,kimi`。`visual` 是通用插槽，不用可不写。

## 二、base_url（大多数情况不用填）

代码默认：
- Qwen → `https://dashscope.aliyuncs.com/compatible-mode/v1`
- Kimi → `https://api.moonshot.cn/v1`

若这两个模型走独立代理端点，再补：
```env
QWEN_VL_BASE_URL=https://<你的 qwen 端点>/v1
KIMI_VL_BASE_URL=https://<你的 kimi 端点>/v1
```
端点需兼容 OpenAI `chat/completions` 图片输入格式。

## 三、容量 / 性能开关（按需调，默认值已给）

| 变量 | 默认 | 作用 |
|---|---|---|
| `REVIEW_PDF_VISUAL_VERIFY_LIMIT` | 6 | 对"已发现问题"做视觉复核的上限 |
| `REVIEW_PDF_VISUAL_VERIFY_LAYOUT_LIMIT` | 6 | 页级版式疑点视觉复核上限 |
| `REVIEW_PDF_VISUAL_VERIFY_PAGE_BUDGET` | 0 | 总页预算，0=不限 |
| `REVIEW_PDF_VISUAL_VERIFY_SCALE` | 1.8 | 页面渲染缩放（1–3） |

首次验证可把两个 LIMIT 调到 2、PAGE_BUDGET 设 10，跑通后再放开，省 token。

## 四、两条独立通道（都已确认存在）

1. **几何信号通道**（`pdf_layout_signals.py`）：纯 fitz 几何计算，不调任何模型，报拥挤行、粗线条、图片偏移、表图编号等疑点。始终可用，用于挑页和排序。
2. **视觉模型通道**（`visual.py` + `ai_client.verify_review_issue_from_image`）：把页面渲染成 PNG 交给视觉模型，对疑点做 confirm/reject 复核，rule 名为 `PDF-VISUAL-001`。需要上面配的 key。

## 五、注意事项

- **DeepSeek 不能用于视觉**：代码里 deepseek 被显式排除在视觉链外（无视觉模型），别把它放进 `REVIEW_VISUAL_PROVIDERS`。
- **qwen3 前缀会触发 thinking 逻辑**：若模型响应异常，可加 `QWEN_ENABLE_THINKING=false` 关闭。
- **key 加载路径**：`runtime_config.bootstrap_runtime_env()` 依次读 `backend/.env` → `backend/runtime.env` → 若干容器路径 → `SMART_DOC_ENV_FILE`。你本地填 `backend/runtime.env` 即可（该文件已被 gitignore，不会进仓库）。
- **无 key 不会崩**：当前状态下视觉阶段会跳过并把 issue 标记为 `provider_unavailable`，审核主流程正常完成。

## 六、补完 key 后如何验证

把上面配置填好后，重跑 T7 审核并在日志里看视觉阶段：
- 应出现 `[审核] 视觉复核 provider=qwen` 之类的调用日志；
- 输出 issues 里应出现 `rule=PDF-VISUAL-001` 的条目；
- 若看到 `provider_unavailable`，说明 key 没被读到，检查填的是 `runtime.env` 还是 `.env`、以及 `REVIEW_VISUAL_PROVIDERS` 是否包含对应 provider。
