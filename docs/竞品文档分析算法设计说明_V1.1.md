## 一、可读性评分模型

### 1.1 总体框架

综合评分 = Σ(维度得分 × 权重)，满分 100。每个维度独立计算 0–100 分并给出样本例句（可点查证据），总分不做任何隐藏修正。

| 维度 | 权重 | 依据 |
|---|---|---|
| 平均句长 sentence_length | 25% | 技术写作规范中句长对可读性影响最直接（ASD-STE100 等规范均以句长为核心管控项） |
| 术语密度 term_density | 20% | 术语堆叠是 B 端手册主要阅读障碍，但合理密度是必要的，权重低于句长 |
| 被动句比例 passive_ratio | 20% | 操作类文档要求明确执行主体，被动句掩盖责任方 |
| 段落长度 paragraph_length | 15% | 影响较低：长段常由长句导致，与句长维度部分重叠，降权避免重复惩罚 |
| 修饰词堆叠 modifier_stack | 20% | 连续定语/形容词堆叠是中文与英文技术文档通病 |

### 1.2 各维度公式与阈值（v1.1 区间制）

v1.1 由 v1.0 的「单向阈值制」（指标 ≤ 满分线即 100 分）改为**区间制**：指标落入理想区间 `[ideal_lo, ideal_hi]` 得满分；低于下限按短侧梯度 `k_short` 扣分，高于上限按长侧梯度 `k_long` 扣分，两侧梯度独立。分数经 `_clamp_score` 限制在 0–100。

```
_band_score(avg, ideal_lo, ideal_hi, k_short, k_long):
  avg < ideal_lo 且 k_short > 0  → 100 − (ideal_lo − avg) × k_short
  avg > ideal_hi 且 k_long  > 0  → 100 − (avg − ideal_hi) × k_long
  否则                           → 100
```

| 维度 | 语言 | 理想区间 | 短侧扣分（k_short） | 长侧扣分（k_long） |
|---|---|---|---|---|
| 平均句长 | 中文 | 15–40 字 | 每短 1 字扣 1.0 分 | 每超 1 字扣 1.5 分 |
| 平均句长 | 英文 | 8–20 词 | 每短 1 词扣 2.0 分 | 每超 1 词扣 3.0 分 |
| 术语密度 | 中/英 | 5%–15% | 每低 5 个百分点扣 10 分（k=200） | 每高 5 个百分点扣 8 分（k=160） |
| 被动句比例 | 中/英 | 0–10% | 不扣分（k_short=0：被动少不是问题） | 每高 5 个百分点扣 10 分（k=200） |
| 段落长度 | 中文 | 30–150 字 | 每短 2 字扣 1.0 分 | 每超 5 字扣 1.0 分 |
| 段落长度 | 英文 | 10–80 词 | 每短 0.4 词扣 1.0 分 | 每超 2 词扣 1.0 分 |
| 修饰词堆叠 | 中/英 | 0 处 | — | 每处扣 4 分（`100 − count × 4`；中文 ≥3 连「X 的」，英文 ≥3 连形容词） |

设计动机（外部评审 P0 采纳项）：
- **短侧也扣分**：v1.0 只罚「过长」，导致电报体短句、零术语密度的浅内容与优质文档同样拿满分，无区分度；
- **被动句只扣高不扣 0%**（用户裁定）：被动句占比 0 不代表文档有问题，`k_short=0` 语义为「低侧不触发扣分」；
- 中英文区间差异依据：中文一字约对应英文 0.5–0.6 词的信息量，15–40 字 ≈ 8–20 词。

### 1.3 综合评级与评级抑制

| 综合分 | 评级 |
|---|---|
| ≥ 85 | excellent |
| ≥ 70 | good |
| ≥ 55 | fair |
| < 55 | poor |

**评级抑制（防误导）**：任一维度 < 55 分时综合评级封顶 fair；任一维度 < 40 分时封顶 poor。触发时报告输出 `level_note` 说明下调原因。

### 1.4 样本量三档（v1.1 新增，外部评审 P0 采纳项）

按提取句数分档，防止「样本不足仍给高分」：

| 样本档位 | 句数 | 行为 |
|---|---|---|
| insufficient | < 100 | **不评分**：维度 score 置 None、综合评分 None、评级 insufficient；报告渲染为「样本不足（未评分）/ 维度 N/A」，并提示改用 PDF 原件或本地 HTML 上传 |
| limited | 100–500 | 正常评分，但综合评分旁显式标注「（样本有限）」，warnings 提示评分仅供参考 |
| sufficient | > 500 | 正常评分，无额外标注 |

客观结构统计（第三节）不受样本档位影响，样本不足时仍输出。

## 二、术语库（term_density 的判定基础）

三层来源，命中任一即计为术语：

1. **内置领域术语**（`_BUILTIN_EN_TERMS`）：测序（sequencing/flowcell/adapter/barcode…）与图像分析（segmentation/ROI/thresholding…）两大领域，约 150 词条；
2. **平台词典**（`app/dictionary/technical_terms.txt`）：与平台其他模块共享；table/figure/step 等普通词已列入排除集；
3. **强术语特征**（无需词条）：含数字的型号（NextSeq 2000、Q30）、含连字符的复合词（RNA-seq）、≥2 字符全大写缩写（DNA、PCR、MGI）。

匹配规则：精确匹配 + 轻量词干（复数 -s/-es/-ies），大小写不敏感。

**术语样本（v1.1 新增，外部评审 P1 采纳项）**：术语维度的问题例句由「零散术语词列表」改为「密术语句子」——收集 ≥3 个术语命中且术语占比 ≥25% 的句子取 top5，作为「术语密度过高」的直接证据，避免把孤立术语词当问题刷屏。

> 历史缺陷（已修复）：旧版以「长度 > 6 的英文单词」判术语，把 technical/information 等普通词全部误报，实测密度虚高至 48.5%。

## 三、结构统计（客观指标，不做主观评分）

| 指标 | PDF 口径 | HTML 口径 | DOCX/MD |
|---|---|---|---|
| 页数 | `doc.page_count` | 恒为 1 | 按 pages_text 兜底 |
| 章节数 | 标题行正则（保守启发式） | `<h1>–<h3>` 标签计数（优先） | 标题行正则 |
| 图片数 | 嵌入图按 xref 去重（复用 logo 不重复计） | 正文区 `<img>` 计数（剔除 nav/header/footer） | 暂不支持（notes 说明） |
| 表格数 | `page.find_tables()` 线框检测（>300 页跳过控耗时；需单元格内有文字） | 正文区 `<table>` 计数 | 暂不支持（notes 说明） |
| 安全警告数 | 行首 WARNING/CAUTION/DANGER/NOTICE/警告/注意/危险/警示（文本关键词标记） | 同左 | 同左 |
| 警告符号（文本层） | ⚠/☠/🛡/🚧/🚫/⛔ 等 unicode 符号计数 | 同左（HTML 分支解析器统计） | 同左 |

**安全警告 0 标注（v1.1 新增，外部评审 P1 采纳项）**：`warning_count == 0` 时自动追加说明「检测依赖文本关键词匹配，图标或特殊排版呈现的安全提示可能未被统计，建议人工复核」，避免把「0 警告」当作竞品合规结论；检测到警告符号时同步提示「疑似图标型安全提示」。

标题行启发式的保守设计：编号标题要求至少两级（如 3.2）以避开「1. 操作步骤」，行长度 ≤ 60 且不以句读结尾，Chapter/Appendix/第X章 直接匹配。计数为近似值，报告中已注明口径。

## 四、编辑工具识别置信度规则

### 4.1 PDF 输入

| 证据来源 | 置信度 | 规则 |
|---|---|---|
| producer/creator 元数据命中 | high | 唯一例外：仅命中 Adobe Acrobat 且无其他工具时降 medium（多半只是「另存为」） |
| 嵌入字体推断宿主工具 | medium | 仅作佐证，不单独定论 |
| 文本指纹（LaTeX 标记/软连字符等） | low | 仅在元数据与字体均未命中时展示 |

**浏览器打印导出识别与内嵌链接反查（v1.1 新增，外部评审 P1 采纳项）**：
- producer 命中 Skia/Chrome/Edge 等打印链路，或 creator 含 Chrome/Edge → 识别为「浏览器打印」类（二手资料），并在报告「导出/来源说明」注明：工具识别仅代表打印链路，无法直接确认原创编辑工具；分页断行为浏览器渲染结果，句长/段落统计可能受影响；
- 对 PDF 用 `page.get_links()` 反查内嵌链接（限 50 页 / 40 条）：命中 `/content/`、`/skins/`、`.htm`、`/topics/` 特征 → 提示「疑似 HAT（如 MadCap Flare）导出」，弥补打印链路无法直接识别原创工具的缺口。

识别库（`_TOOL_PATTERNS`，25 条模式、19 种工具）：InDesign、FrameMaker、QuarkXPress、Pandoc、DITA-OT（producer "DITA Open Toolkit"/"dita-ot"/"ditaot"）、oXygen XML Editor、LaTeX 三变体（pdfTeX/XeTeX/LuaTeX，泛化条目自动去重）、Word、LibreOffice、OpenOffice、WPS、Distiller、Acrobat、Prince XML、PDFium、Chrome/Edge 打印、macOS Quartz、Pages。

### 4.2 HTML 输入（证据链模型）

每个工具按独立证据计数：**≥2 条 → high，1 条 → medium，0 条 → 未知**。

| 工具 | 证据类型 |
|---|---|
| MadCap Flare | URL 含 /Content/ 或 /Skins/、脚本依赖 MadCap*、CSS 位于 Skins/Content 目录、data-mc-* 属性、MadCapAll.js 引用 |
| Adobe RoboHelp | whutils/whmsg/whver/whstub.js 脚本、rgforms/RoboHelp 标记 |
| DITA-OT | URL 含 /topics/、/concepts/、/tasks/，class 含 topic/concept/task（排除 task-list 等扩展类名），data-dita-* 属性，meta generator |
| 文档站点框架 | meta generator（Docusaurus/VitePress/VuePress/GitBook/Sphinx/MkDocs/ReadMe），medium |

同一工具被结构特征与 meta generator 同时命中时证据合并、可升 high，不产生重复条目。

## 五、HTML 正文抽取与入口页识别

- 剔除 nav/header/footer/aside/script/style/form/template 等骨架标签内全部文本；
- 优先取 `<main>`/`<article>` 正文，正文 ≥ 400 字符才采用，否则回退全页（已去噪）并输出「JS 渲染受限」警告；
- 抓取安全：仅公网 http/https（DNS 解析校验，拒环回/私网/保留地址）、仅 80/443、5 MB 上限、20 s 超时；
- **入口页识别（v1.1 新增，用户裁定「只识别+提示，不递归爬取」）**：URL 路径含 `/frontpages/`、`/index`、`/home`、`/default`、`/toc` 等特征，或全文 < 500 字符 → 报告提示「当前为封面/导航页，建议选择子页面或上传完整 HTML 包」，不自动爬取子链接（递归抓站放 Phase 2）。

## 六、洞察引擎（v1.1 四分类重构）

规则层（确定性）输出四类洞察，去重（area + action 前 20 字）后 P1 在前、最多 10 条：

| 类别 | 触发 | 优先级 |
|---|---|---|
| 竞品弱项机会 | 维度得分 < 55 | P1 |
| 竞品基准（高分合并） | 维度得分 ≥ 85，合并为单条，evidence 附前三强维度 | P2 |
| 中分改进空间 | 维度得分 55–70 | P2 |
| 竞品基准/工具链/图文密度/安全警告/对比基线/总体 | 工具链双形态（在线+打印 PDF）、图文比、warning=0 风险、我方优劣占位（无基线时引导录入）、总体评级 | P1/P2 |

**v1.1 变化（外部评审 P1 采纳项）**：v1.0「逐维度刷对标检查」导致洞察同质化刷屏，v1.1 将高分维度合并为单条「竞品基准」，新增结构图文密度、安全警告风险、对比基线占位三类；「我方优势/劣势」需我方手册基线数据，无基线时以占位条引导（用户裁定：四类全做，占位待数据）。

AI 层可选（`COMPETITOR_AI_INSIGHT` 开关），仅接收结构化指标（不传全文，token 成本恒定约 1k），失败自动降级为纯规则。

多文档对比（另见代码文档）：2–5 任务维度分数矩阵 + 并列最高分标记 + 综合排名 + 雷达图；有我方基线时逐维度 Δ≥8 报差距，无基线时极差 ≥15 报分化点。

## 七、报告渲染口径（v1.1 同步）

- 样本不足：综合评分「样本不足（未评分）」、评级「—」、维度表 N/A、跳过「典型问题例句」；
- 样本有限：综合评分旁标注「（样本有限）」；
- 典型问题例句：仅展示得分 < 75 的维度（高分维度不吹毛求疵）；例句过滤标题/图表题注/规格数字行（如 "1500 VA LCD"、"111 cm (43.7 in)"）等非问题行；
- 工具识别章节：新增「导出/来源说明」块（浏览器打印偏差 + HAT 链接反查提示）；
- 结构统计章节：安全警告行标注「文本关键词标记」，warning=0 与符号计数以说明块展示。

## 八、已知局限与校准方法

### 8.1 已知局限（诚实披露）

1. 章节数为启发式近似值（无 PDF 大纲时按标题行正则）；
2. PDF 表格检测依赖线框与单元格文字，无边框/样式化表格可能漏计；
3. 被动句判定为规则式（中文「被/受到/由…完成」，英文 be+过去分词），存在漏判/误判；
4. 术语库以测序/图像领域为主，其他领域（超声等）密度指标偏低需扩充词条；
5. 权重与阈值 v1.1 为工程经验值（区间制参数已按保守方向设定），**尚未用大规模真实手册集校准**；
6. 警告符号统计依赖文本层 unicode 符号，嵌入图片中的警告图标无法统计（已提示人工复核）。

### 8.2 校准方法（CLI）

```bash
cd backend
python scripts/calibrate_competitor.py <手册文件或目录>... --out calibration.md
```

输出逐文档原始指标 + 评分 + 中位数分布。复核准则：

- 公认优质的手册某维度普遍 < 70 分 → 该维度区间过窄或梯度过严，放宽；
- 公认晦涩的文档普遍 > 85 分 → 梯度不足，加严；
- 调整后修改 `_dim_*` 函数中的区间/梯度参数，重跑校准直至分布合理，再同步更新本文档版本号。

> 报告页脚「评分方法：规则引擎 v1.1」即指向本文档；算法调整后必须递增版本并在本文档记录变更。
