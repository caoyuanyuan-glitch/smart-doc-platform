## 1. 项目背景

技术文档部门需要定期对竞品（如 Illumina、Thermo Fisher 等）的产品说明书/帮助中心进行系统性分析，输出可量化的对比报告，用于指导华大智造（MGI）文档改进方向。

当前痛点：竞品分析依赖人工浏览和主观判断，缺乏标准化、可复用的自动化分析工具。

**目标用户与使用场景：** 技术文档工程师（本模块的主要使用者）需要定期分析竞品手册，评估其编写质量与多维度体验（可读性、易查找性、可用性、可获得性），并将分析结论沉淀为对比报告，作为内部文档改进的参考依据。典型使用流程：上传竞品 PDF 或输入帮助中心 URL → 自动完成多维度分析 → 查看结构化报告 → 导出 Markdown/JSON/Excel 对比矩阵。

---

## 2. 模块定位

**模块名称：** 竞品文档分析模块（引擎：Competitor Doc Analyzer）

> 说明：本模块统一命名为"竞品文档分析模块"。范围聚焦"竞品**文档**"（产品说明书、帮助中心、在线手册）的质量与可获得性分析，不等同于广义的竞品分析（价格/市场/渠道等不属本模块范围）。

**核心目标（完整愿景）：**
- 输入竞品文档（PDF 或 URL），自动输出结构化分析报告
- 支持多维度质量分析：编辑工具识别、可读性、易查找性、可用性、可获得性、内容深度
- 支持批量分析，生成横向对比矩阵
- 分析维度可配置，结果可导出为 Markdown/JSON/Excel

> 说明：上述为模块完整愿景。各能力落地优先级以 §7 迭代计划为准，其中 MVP（Phase 1）范围仅包含 PDF 上传、工具识别、可读性分析及 Markdown 报告输出；易查找性、可用性、可获得性分析及 HTML 输入等能力在 Phase 2 及以后交付，不视为 MVP 验收项。

**非目标（明确排除）：**
- ❌ 不做翻译模块（其他部门负责）
- ❌ 不做截图-文字一致性校验
- ❌ 不做合规性检查（NMPA/FDA 法规）
- ❌ 不做审校工作流（接受/驳回/讨论）
- ❌ 不做多语言同步追踪
- ❌ 不做发布渠道分发

**模块边界（与平台其他模块的关系）：**
| 模块 | 边界 |
|---|---|
| 文档审核（Review） | 审核模块面向**内部文档**的合规与质量检查；本模块面向**外部竞品文档**的质量评估，两者不重叠 |
| 文档对比（Compare） | 对比模块用于同一文档不同版本的差异比对；本模块用于单份竞品文档的多维度质量分析 |
| 翻译 / 问答 / 生成 | 无直接依赖；本模块输出的 JSON 结构可供其他模块作为数据源 |

## 3. 功能需求

### 3.1 编辑工具识别

**功能描述：** 自动判断竞品文档使用的编辑/排版工具（HAT / 桌面排版 / 文字处理）。

**输入：** PDF 文件 或 HTML 页面 URL

**检测指标：**

| 检测维度 | PDF 检测方式 | HTML 检测方式 |
|---|---|---|
| 工具名称 | PDF 元数据（Producer/Creator） | URL 路径特征、脚本依赖、CSS 目录结构 |
| 字体列表 | 嵌入字体族分析（PDF 页字体列表） | — |
| 文件结构 | 目录层级、书签结构 | Content/Skins/Scripts 目录特征 |
| 置信度 | 高/中/低三级 | 高/中/低三级 |

**工具识别库（一期支持，配置化可扩展）：**
- MadCap Flare（HTML 帮助中心）
- Adobe InDesign（PDF）
- Adobe FrameMaker（PDF）
- Microsoft Word（PDF）
- 未知/其他

**置信度判定规则：**

| 置信度 | 判定规则 |
|---|---|
| 高（high） | 命中 ≥2 条独立证据，且关键证据（如 PDF Producer 精确匹配工具名）成立 |
| 中（medium） | 仅命中 1 条证据，或证据存在模糊匹配 |
| 低（low） | 仅有弱特征线索，无法确认工具归属（归入"未知/其他"） |

**输出示例：**
```json
{
  "tool": "MadCap Flare",
  "confidence": "high",
  "evidence": [
    "URL path: /Content/IN/.../Topic.htm",
    "Scripts: require.min.js, foundation.min.js",
    "Skins: /Skins/Default/Stylesheets/Topic.css"
  ]
}
```

### 3.2 可读性分析

**功能描述：** 量化分析文档的语言可读性指标，并输出综合可读性评分。

**输入：** 文档文本（支持中英文）

**分析指标：**

| 指标 | 英文计算方式 | 中文计算方式 | 阈值参考 |
|---|---|---|---|
| 平均句长 | 总词数 ÷ 句子数 | 总字数 ÷ 句子数 | 英文 <20 词/句，中文 <25 字/句 |
| 术语密度 | 专业术语词数 ÷ 总词数 | 专业术语字数 ÷ 总字数 | <15% 为易读 |
| 被动句比例 | 被动句数 ÷ 总句数 | 被动句数 ÷ 总句数 | <30% 为佳 |
| 平均段落长度 | 总词数 ÷ 段落数 | 总字数 ÷ 段落数 | <150 词/段（英文），中文 <200 字/段 |
| 修饰语堆叠度 | 连续修饰短语（of/in 引导的限定语堆叠 ≥2 层）句子占比 | 连续"的/地/得"结构堆叠句子占比 | <10% 为佳，≥25% 判定为过高（句子缠绕） |

**句子切分与被动句检测规则：**
- 句子切分：按句号、问号、感叹号及换行符切分（中英文统一）；英文首字母缩写（如 e.g.、i.e.）不视为句末。
- 中文被动句检测：匹配"被/由/遭/受/为…所"等被动结构，不限于"被/由"二字。
- 英文被动句检测：匹配 `be 动词 + 动词过去分词`（如 is/was/are/were/been/being + V-ed）。

**专业术语库（一期内置）：**
- 测序领域通用术语（DNA、RNA、sequencing、base call 等）
- 图像分析领域术语（segmentation、threshold、ROI、marker 等）
- 用户可自定义扩展（CSV 上传，见 §5.3）

**综合可读性评分（readability_score）算法：**

各指标归一化后加权求和，得到 0~100 分：

```
指标得分 = 该指标原始值映射到 [0,1] 区间（越优越接近 1）
readability_score = 100 × Σ(指标得分 × 权重)

权重分配：
  平均句长      25%
  术语密度      20%
  被动句比例    20%
  平均段落长度  15%
  修饰语堆叠度  20%
```

**分级标准：**

| 等级 | 分值区间 | 含义 |
|---|---|---|
| excellent | ≥85 | 整体易读，无需针对性优化 |
| good | 70~84 | 可读性良好，个别指标可优化 |
| fair | 55~69 | 存在明显可读性问题，建议按指标逐项改进 |
| poor | <55 | 可读性差，需重点改进 |

**输出示例：**
```json
{
  "language": "en",
  "avg_sentence_length": 16,
  "term_density": 0.12,
  "passive_ratio": 0.08,
  "avg_paragraph_length": 32,
  "modifier_stacking": "low",
  "readability_score": 82,
  "readability_grade": "good"
}
```

### 3.3 可获得性（Access）分析

**功能描述：** 评估文档的获取门槛和访问体验。

**输入：** 文档 URL 或 PDF 文件

**分析维度：**

| 维度 | 检测方式 | 分级 | 检测方式 | PDF 输入适用性 |
|---|---|---|---|---|
| 获取门槛 | 是否需要注册/登录 | 无门槛 / 需邮箱 / 需客户账号 | 人工辅助（试探访问） | 适用 |
| 格式选择 | 支持格式种类 | PDF only / PDF+HTML / 多格式 | 自动（抓取页面链接） | 适用 |
| 搜索功能 | 是否有站内搜索（检测数据与 3.4 易查找性「站内搜索」共享，输出口径以 3.4 为准） | 有 / 无 | 自动（检测搜索框特征） | N/A（PDF 无站内搜索） |
| 移动端适配 | viewport / 响应式布局 | 响应式 / PDF 硬排 / 无适配 | 自动（检测 viewport meta 与媒体查询） | N/A（PDF 无响应式概念） |
| 多语言支持 | 语言选项数量 | 单语言 / 中英 / 多语言 | 自动（检测语言切换入口） | N/A（PDF 语言不可自动枚举） |
| 版本透明度 | 是否标注版本号/修订日期 | 有 / 无 | 自动（文本检索版本关键词） | 适用 |
| 离线可用性 | 是否支持离线下载 | 可下载 / 在线-only | 人工辅助 | 适用（PDF 本身可离线） |

**多语言分级映射规则：** 语言选项数量 = 1 → 单语言；= 2 → 中英；≥ 3 → 多语言。

**自动化与人工辅助说明：** 检测方式标注为"人工辅助"的维度，系统提供检查项清单与输入界面，由分析人员在报告生成前确认；标注"自动"的维度由系统自动检测。标注"适用"的维度在 PDF 输入下正常检测；标注"N/A"的维度在 PDF 输入下输出 `null` 并在报告中注明"该维度不适用于 PDF 输入"。

**输出示例：**
```json
{
  "access_barrier": "none",
  "formats": ["html5", "pdf"],
  "has_search": true,
  "mobile_adaptation": "responsive",
  "languages": ["en", "zh"],
  "version_transparency": true,
  "offline_available": true
}
```

### 3.4 易查找性（Findability）分析

**功能描述：** 评估用户能否快速找到所需内容（信息可发现性）。V1.2 新增维度。

**输入：** HTML 页面 URL（主）；PDF 文件（部分维度）

**分析维度：**

| 维度 | 检测方式 | 分级 | PDF 输入适用性 |
|---|---|---|---|
| 站内搜索 | 检测搜索框/搜索表单（input[type=search]、form action、搜索接口路径） | 有且支持关键词高亮 / 有 / 无 | N/A |
| 目录（TOC） | 检测目录结构（nav 元素、TOC 类元素、H1-H6 大纲层级） | 完整 / 部分 / 无 | 适用（书签/目录页） |
| 面包屑导航 | 检测面包屑（aria-label="breadcrumb"、层级链接序列） | 有 / 无 | N/A |
| 索引与术语表 | 检测 index/glossary 页面入口链接 | 有 / 无 | 适用（文末索引/术语表） |
| URL 语义化 | 路径是否语义化 slug（如 /Content/IN/.../Topic.htm）vs 参数化/数字路径 | 语义化 / 半语义 / 无意义 | N/A |
| SEO 元数据 | title、meta description、canonical、lang 属性完整性 | 完整 / 部分 / 缺失 | N/A |
| 关键内容直达 | 首页是否含高频任务直达入口（Quick links、热门主题、常用操作） | 有 / 无 | N/A |

**分级映射规则：**
- 目录（TOC）完整性：H1-H6 大纲 ≥4 层且导航可展开 → 完整；2~3 层 → 部分；<2 层或缺失 → 无。
- URL 语义化：路径含可读关键词且无冗长 query → 语义化；含关键词但带 query 参数 → 半语义；纯参数/数字路径 → 无意义。
- SEO 元数据：title + description + canonical + lang 四项齐全 → 完整；缺 1~2 项 → 部分；缺 ≥3 项或关键项（title）缺失 → 缺失。

**自动化与人工辅助说明：** 全部维度为自动检测。PDF 输入下 N/A 维度输出 `null` 并在报告中注明"该维度不适用于 PDF 输入"。

**输出示例：**
```json
{
  "has_search": true,
  "search_highlight": true,
  "toc_completeness": "full",
  "has_breadcrumb": true,
  "has_index_glossary": true,
  "url_semantic": "semantic",
  "seo_metadata": "partial",
  "quick_links": true
}
```

### 3.5 可用性（Usability）分析

**功能描述：** 评估用户使用文档完成任务的有效性与顺畅度。V1.2 新增维度。

**输入：** 文档 URL 或 PDF 文件

**分析维度：**

| 维度 | 检测方式 | 分级 | PDF 输入适用性 |
|---|---|---|---|
| 链接有效性 | 抽查站内链接状态码（默认 50 个，可配置；200/404/重定向） | 死链率 0% 优 / <5% 良 / ≥5% 差 | 适用（目录/引用链接抽查） |
| 步骤完整性 | 操作步骤是否编号、是否含前置条件与预期结果 | 完整 / 部分 / 缺失 | 适用 |
| 错误恢复信息 | 是否有 troubleshooting / FAQ / 错误码表章节 | 有 / 无 | 适用 |
| 信息一致性 | 术语、格式、标题风格一致性（抽样比对） | 高 / 中 / 低 | 适用 |
| 页面性能 | 页面大小、抓取耗时（HTML） | 快（<1s）/ 中（1~3s）/ 慢（>3s） | N/A |
| 搜索有效性 | 搜索是否返回结果页（检测 search 结果页特征） | 可用 / 不可用 | N/A |

**自动化与人工辅助说明：** 链接有效性、页面性能、搜索有效性为自动检测；步骤完整性、错误恢复信息、信息一致性为规则初检 + 人工辅助确认（系统给出检查项清单与证据，由分析人员在报告生成前确认）。

**输出示例：**
```json
{
  "dead_link_rate": 0.02,
  "link_check_samples": 50,
  "step_completeness": "full",
  "has_error_recovery": true,
  "consistency": "high",
  "page_performance": "fast",
  "search_works": true
}
```

### 3.6 内容深度分析

**功能描述：** 分析文档的信息覆盖深度和结构特征。

**输入：** 文档文本（支持结构化提取）

**分析维度：**

| 维度 | 计算方式 | 说明 |
|---|---|---|
| 信息架构深度 | 标题层级统计（H1-H6），输出最大有效层级 | 越深则内容组织越细 |
| 操作步骤粒度 | 步骤总数 ÷ 功能模块数 | 功能模块数 = 二级标题（H2）数量；越细则操作越详尽 |
| 参数解释深度 | 含"范围/默认值/影响"的参数比例 | 参数 = 参数表条目或含参数名+取值描述的语句；越高则越专业 |
| 可视化密度 | 图片数 ÷ 总页数 | 越高则越直观 |
| 场景覆盖度 | 边缘场景（故障/异常/优化）章节占比 = 此类章节数 ÷ 总章节数 | 越高则越完善 |
| 辅助信息完整度 | FAQ/术语表/错误代码表/索引的存在性 | 布尔值累加（满分 4） |

**数据来源说明：** 上述指标优先复用文档解析层输出的章节结构（chapters）与段落数据，具体口径见 §6.1 验收标准。

**输出示例：**
```json
{
  "info_architecture_depth": 4,
  "step_granularity": 12,
  "parameter_explanation_depth": 0.65,
  "visualization_density": 2.3,
  "scenario_coverage": 0.4,
  "auxiliary_info_score": 3
}
```

## 4. 非功能需求

### 4.1 输入支持

| 输入类型 | 支持方式 | 优先级 |
|---|---|---|
| PDF 文件上传 | 本地文件 / URL 下载 | P0 |
| HTML 页面 URL | 实时抓取（优先静态解析；JS 渲染页面标注为受限场景） | P0 |
| 本地 HTML 文件上传 | 用于 JS 渲染/受限站点人工保存页面后上传分析 | P1 |
| DOCX/Word | 复用平台现有 docx 解析能力 | P1 |
| 批量输入 | 多文件 / URL 列表 | P1 |

> 说明：① DOCX/Word 因平台已具备 `parse_docx` 解析能力，由 V1.0 的 P2 提升为 P1。② 本地 HTML 文件上传为 V1.2 新增（P1）：针对 JS 渲染站点无法直接抓取、或目标站点对抓取有限制时，允许分析人员手动保存页面后上传。

### 4.2 输出格式

| 输出格式 | 说明 | 优先级 |
|---|---|---|
| Markdown | 单文档分析报告 | P0 |
| JSON | 结构化数据，供下游系统消费 | P0 |
| Excel/CSV | 横向对比矩阵 | P1 |
| 可视化图表 | 雷达图、柱状图对比 | P2 |

### 4.3 性能要求

- 单文档分析耗时 < 30 秒（PDF < 50MB）
- 批量分析：系统全局并发上限 5 个任务；超出部分进入排队队列，按提交时间先后执行
- HTML 页面抓取支持超时重试（3 次，重试间隔按指数退避：5s / 10s / 20s）
- HTML 站内链接抽查上限默认 50 个（可配置），避免过度抓取；抓取行为遵守目标站点 robots.txt，仅用于内部质量评估

## 5. 技术方案建议（供参考，落地时以平台现有技术栈为准）

### 5.1 架构设计

```
[输入层] → [解析层] → [分析引擎] → [报告生成]
   ↓            ↓            ↓            ↓
 PDF/URL    doc_parser   规则引擎      Markdown
            (pymupdf)    可选 AI 增强   JSON/Excel
```

### 5.2 关键技术选型（复用平台现有能力）

> 修订说明：V1.0 中建议的 PyPDF2/PDFMiner、NLTK/spaCy、Celery/RQ、Playwright/Selenium 等与平台现有技术栈不一致。V1.1 调整为**优先复用平台已具备的能力**，避免重复建设与依赖冲突。

| 模块 | 方案 | 说明 |
|---|---|---|
| PDF 解析 | 复用 `app/utils/doc_parser.py`（pymupdf） | 提取文本、元数据、章节结构 |
| PDF 元数据/字体 | pymupdf（fitz）原生能力 | `doc.metadata` 取 Producer/Creator，`page.get_fonts()` 取字体列表 |
| HTML 抓取 | requests + BeautifulSoup（后续引入） | 优先静态解析；JS 渲染页面列入后续增强项；链接有效性检查用 requests 状态码（抽查上限 50 个，可配置），遵守 robots.txt |
| 中文分词 | jieba（平台已有） | 分词、术语统计 |
| 文本分析 | 规则算法为主；AI 增强走 `app/utils/ai_client.py` | MVP 纯规则；Phase 2 起用 AI 生成改进建议 |
| 报告生成 | 参照 `app/utils/compare_utils.py` 的 render 模式 | Markdown/JSON 输出 |
| 任务调度 | FastAPI 同步接口 + 前端超时兜底；批量场景用后台任务/轮询 | 不引入 Celery 等重依赖 |

### 5.3 术语库维护

- 内置基础术语库（测序+图像分析）
- 支持用户上传自定义术语表（CSV 格式）
- 术语命中规则：精确匹配 + 词干匹配（仅英文）+ 大小写不敏感

## 6. 验收标准

### 6.1 功能验收

| 功能 | 验收标准 |
|---|---|
| 编辑工具识别 | 对已知工具（MadCap/InDesign/Word）识别准确率 > 90% |
| 可读性分析 | 各指标计算正确；综合评分与人工判断一致性 > 85% |
| 易查找性分析 | 7 个维度均可输出（PDF 输入下适用维度全部检出，N/A 维度输出 null 并注明）；自动维度检测结果准确 |
| 可用性分析 | 链接抽查执行成功（样本数可配置，默认 50）；步骤完整性/错误恢复/一致性维度按"规则初检 + 人工辅助确认"流程产出 |
| 可获得性分析 | 7 个维度均可输出（PDF 输入下适用维度全部检出，N/A 维度输出 null 并注明）；自动维度检测结果准确 |
| 内容深度分析 | 6 个维度可计算，结果可复现 |

**验收样本集（新增/修订）：**
- 样本来源：Illumina 官方文档（4 份，见 §8.1）+ Thermo Fisher 手册 1 份 + 内部自建样例文档 1 份，共 6 份（PDF 输入）。
- 样本性质：其中 5 份为已知工具生成的文档（MadCap Flare ×2、InDesign ×1、Word ×1、FrameMaker ×1），1 份为未知工具文档，用于识别准确率测试。
- 可读性人工评分标准：由 2 名技术文档工程师独立对样本按"易读性 1-5 分"评分，取均值作为人工基线，与系统综合评分（映射到 1-5 分）比对，一致率 = |系统-人工| ≤ 1 分的样本占比，需 > 85%。
- **HTML 样本（V1.2 新增）：** Illumina 帮助中心页面 2 个（§8.1 的 HTML URL 示例及其 1 个子页面），用于易查找性/可用性/可获得性维度验收；PDF 输入下对应 N/A 维度输出 `null` 并注明。

### 6.2 输出验收

- Markdown 报告格式统一，可直接归档
- JSON 数据结构稳定，字段不随意变更（字段变更需升版本并更新本文档）
- Excel 对比矩阵支持多文档横向对比
- 编辑工具识别输出须包含字体列表（提取完整、可追溯）

## 9. 附录

### 9.1 术语定义

| 术语 | 定义 |
|---|---|
| HAT | Help Authoring Tool，帮助文档创作工具（如 MadCap Flare） |
| PDF Producer | PDF 元数据中的生成工具标识 |
| 响应式布局 | 根据屏幕尺寸自动调整页面布局 |
| 术语密度 | 专业术语在全文中的占比 |
| 可读性评分 | 本模块定义的 0~100 综合评分，由五类指标加权计算（见 §3.2） |
| 被动句比例 | 被动结构句子在总句数中的占比 |
| 可视化密度 | 文档图片数量与总页数的比值 |
| 场景覆盖度 | 边缘场景（故障/异常/优化）章节在总章节中的占比 |
| 易查找性（Findability） | 用户能否快速找到所需内容的能力；本模块通过站内搜索、目录、面包屑、索引、URL 语义化、SEO 元数据、关键内容直达等维度评估（见 §3.4） |
| 可用性（Usability） | 用户使用文档完成任务的有效性与顺畅度；本模块通过链接有效性、步骤完整性、错误恢复信息、信息一致性、页面性能、搜索有效性等维度评估（见 §3.5） |
| 面包屑（Breadcrumb） | 页面顶部的层级导航路径，指示当前页在站点结构中的位置 |
| 死链率 | 抽查链接中返回 404/无法访问的比例 |
| 语义化 URL | 路径包含可读关键词、能反映内容主题的 URL |
| SEO 元数据 | HTML 中的 title、meta description、canonical、lang 等供搜索引擎/辅助工具读取的标签 |
