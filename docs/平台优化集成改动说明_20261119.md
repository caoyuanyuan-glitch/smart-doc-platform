## 关键决策：为什么不把意见原文塞进 prompt

原始评估建议"把 comment 原文写进 basis section"。实施前查到这是**用户为防误报有意做的修复**：
- commit `42733b2 fix(review): reduce false positives`（2026-08-17）把 comment 从 section text 移除；
- 测试 `test_load_cyy_human_review_basis_sections_omits_comment_details` 明确断言原文不得进入；
- 原因：把旧文档的具体错误（如"步骤3跳到步骤5"）塞进新文档审核，模型会照搬臆造——正是用户反复驳回的误报类型。

**经用户确认，改为"抽象问题模式清单"方案**：只输出"该类问题长什么样、什么条件下报"的抽象描述，不含任何具体文档错误原文。

### 修改
- `backend/app/api/review.py`
  - `_build_ai_review_basis_sections`：聚合时追加抽象模式清单（try/except 包裹，失败不影响主流程）。
